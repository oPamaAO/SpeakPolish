# Голосовой ввод для opencode — что это и как пользоваться

## Что это
Два инструмента, оба глобальные (работают в любом проекте и чате):
1. **Диктовка** — `voice.py` слушает микрофон, распознаёт локально через Whisper
   (`large-v3-turbo`, твоя GTX 1660S тянет, в интернет ничего не уходит).
2. **Кнопка «конфетка»** — субагент `prompt-polisher` + команда `/polish`
   превращают сырой надиктованный текст в структурированное ТЗ. Бесплатная модель
   `opencode/muse-spark-1.3-contributor-free`, ничего не правит в проекте (все инструменты запрещены).

## Как пользоваться
1. Запусти фоном: `python voice.py` (оставь окно висеть; для хоткеев на Windows
   запускай терминал **от администратора**).
2. `F9` — старт записи, ещё раз `F9` — стоп. В чат вставляется **только новый кусок**,
   а весь текст копится в `draft.txt`. Можно: стоп → подумать →
   подправить руками → снова `F9` → говорить дальше.
3. `Shift+F9` — то же самое (алиас «продолжить»).
4. `Ctrl+F9` — очистить черновик, начать заново.
5. `Ctrl+Shift+Space` — отполировать **весь `draft.txt`**, результат **заменяет**
   текст в поле ввода (выделяет всё, включая многострочность, и вставляет).
   Перед заменой 2 сек на возврат фокуса — не трогай клавиатуру.
   Кликни в поле ввода opencode ДО хоткея: замена бьёт туда, где курсор.
   Правила полировки вшиты в скрипт (не зависят от agent-файла).
   Режим меняется в `config.yaml` (`polish.mode: replace|append`).
   Важно: источник полировки — `draft.txt`, чат — только отображение. Ручные правки
   в чате в полировку не попадут.
5б. Без голосового ввода: выделил свой текст → `Ctrl+C` → `F10` — тот же улучшатель
   отполирует содержимое **буфера обмена** и заменит текст в поле ввода.
6. Тишина дольше ~2 сек, хвосты тишины и типовые выдумки Whisper («спокойная музыка»,
   зацикленные повторы) вырезаются автоматически; списки — в `config.yaml`.
7. Держать файл открытым: запусти `open_draft.bat` — черновик откроется в VS Code
   и будет дописываться вживую, искать ничего не надо. Консоль скрипта также
   показывает каждый кусок и общий размер черновика.
8. Автозапуск: ярлык `voice-opencode` уже лежит в автозагрузке Windows
   (свёрнутое окно). Убрать: удали ярлык из `shell:startup`.
9. Архив записей `recordings/` — последние 20 сырых кусков аудио. Если текст
   потерялся — слушаем wav и видно, где потеря: в микрофоне или в STT.
10. После правок `agents/*.md` и `commands/*.md` перезапусти opencode —
    иначе подхватится старая версия промптов.
11. При старте скрипт печатает сборку (сейчас `2026-10-15f`) и микрофон.
    Не та сборка = запущен старый процесс, убей его.
12. Микрофон: после каждого куска пишется `Уровень: пик X, речи Y%`.
    Норма: пик >0.1, речи >30%. Меньше — проверяй громкость/выбор микрофона
    в Windows; сменить микрофон: `config.yaml` -> `audio.device`.
    Тихие записи скрипт подтягивает авто-усилением, но чудес не бывает.
6. Без голоса: в любом чате opencode напиши `/polish <сырой текст>`.

## Файлы
| Файл | Зачем |
|---|---|
| `voice.py` | запись, STT, хоткеи, вызов полировки |
| `config.yaml` | модель, хоткеи, агент/модель полировки |
| `terminology.yaml` | «как услышалось → как пишем» (эм си пи → MCP). Только однозначное! Дополняй своими словами |
| `draft.txt` | текущий черновик (append-буфер) |
| `../agents/prompt-polisher.md` | сам полировщик, правила ТЗ |
| `../commands/polish.md` | команда `/polish` |

## Если что-то пошло не так
- `Free-tier guard` при полировке — free-модель иногда режет вызовы из `run`.
  Черновик цел: вставь его в TUI и вызови `/polish` там.
- Хоткеи не срабатывают — перезапусти терминал от администратора.
- CUDA не взлетела — скрипт сам упадёт на CPU (медленнее, но работает).
- Плохо расслышал термин — добавь пару «услышалось → правильно» в `terminology.yaml`.
